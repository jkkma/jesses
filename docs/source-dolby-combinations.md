# Source Dolby tone-map combinations

The source Quick Convert graph retains compressed HEVC/RPU until libplacebo renders the picture. Its output-side `-ss/-t` is after the complete graph; earlier frames therefore participate in adaptive brightness detection in Exact/Frame modes. InputSeek is before the original decoder. Tone mapping precedes explicit FPS resampling, bitmap overlay, geometry, text and custom rows. CPU encoders remain the only video encoders; Spline uses Vulkan processing.

`ToneMapSettings.sourceWorkflow` is optional/defaultfalse and has no visible control. The source ordinary/image/batch/held adapters freeze true when tone mapping is enabled. A valid parsed single-layer profile8.1 HDR10-compatible configuration permits the source's CPU base-layer rendering or Auto/Hable fallback without inventing a base-layer checkbox. Legacy explicit requests retain their opt-in. Profile5 cannot use CPU base-layer fallback. Explicit Spline/GPU cannot silently become Hable when Vulkan is unavailable.

Source CPU rendering also freezes the literal fork calibration: PQ `npl=266.667`, peak divided by that anchor and rounded using the source's three-decimal formatter, and the `gbrp16le → zscale(matrix=bt709,range=tv) → yuv444p16le` clamp. HLG retains the source defaults instead of forcing PQ exposure. The historical explicit API's 100-nit path remains separate. The source clamp requires FFmpeg's ordinary pixel-format conversion; capability validation permits that conversion and still verifies the complete selected 10-bit output. Earlier coherent 100-nit source-flagged results are retained as `previous-coherent-cpu-qualification.json`, not presented as literal source brightness.

The standalone source clock path scans every original decoded frame, requires finite strictly increasing timestamps and stable geometry/pixel/color properties, and validates the RPU and parsed Dolby metadata for every GPU-rendered frame. It retains the compressed input through right-angle display rotation/tone mapping rather than normalizing it to FFV1 beforehand. The actual producer counters, complete coded checkpoint decode and final decode establish the resulting count/geometry/CFR contract. Original file, tool, recovery and publication guards remain in force. Copied audio/subtitle clocks are not replaced by the observed video contract.

That complete decoded scan now runs beside the encoder rather than before it. The frame count and strictly increasing clock are planned from every packet's presentation time and a fully checked first decoded frame; the unchanged per-frame validator (timestamps, geometry, pixel format, color, static HDR, RPU and parsed Dolby metadata) must then pass the whole source before publication. Any rejection, or a decoded count/clock/HDR plan that differs from the packets, stops the encoder and fails the job. Packets without presentation times, discarded or corrupt packets, a non-keyframe first packet or a first decoded frame that is not the first packet time keep the previous blocking scan. See [the libplacebo provider notes](vulkan-libplacebo-provider.md#complete-source-verification-beside-the-encoder).

Evidence is under `target/migration-validation/dolby-combinations-20261102/`; `scripts/qualify-source-dolby-combinations.py` reproduces independent literal-graph, full-output and packet/sample checks against the retained JobManager outputs. No downloaded footage is checked into Git.

Linux uses the qualified CPU-only FFmpeg9/Vulkan/libplacebo delivery and physical AMD Radeon 890M RADV GFX1150. Every final frame is decoded and checked for 10-bit limited BT709 and removal of stale HDR/Dolby metadata. The final qualification receipt contains13 cases; `source-calibrated-independent-proof.log` updates only the four affected CPU/AV1AN rows and retains the unaffected GPU/Spline evidence. `browser-final.log` is5/5 source admission-marker snapshot tests; `admission-unit.log` proves legacy/source opt-in separation, exact CPU calibration and malformed compatible-base rejection; `clock-unit.log` preserves legacy strict CFR while source AV1AN admits monotonic original ordinals; `held-spline-unavailable.log` proves held no-device behavior.

The AV1AN gate exposed and fixed a real tool-selection conflict: placing `/usr/bin` first for selected x264 also selected its older FFmpeg, despite the job stamping qualified FFmpeg9. The launcher now prioritizes the selected media-tool folders and verifies every canonical hardcoded child name against its selected/stamped file. A conflicting sibling cycle fails clearly instead of executing another provider. `child-tools-unit.log` proves selected FFmpeg/FFprobe and x264 execution with a foreign FFmpeg next to the encoder, plus explicit cycle rejection. Final real AV1AN CPU outputs and independent engine references both use the qualified FFmpeg9 pair.

This phase does not claim dual-layer/FEL reconstruction, non-right-angle transforms, interlace reconstruction before Dolby rendering, or native Windows Vulkan output. The separately admitted source AV1AN compatible-base route covers positive-origin and monotonic VFR inputs with no display transform; it uses a distinct original-clock allowance, never the source-cut flag or encoded mixed-region contract. Windows handoff should run the same actual CPU+physical-Vulkan graph, no-device held/edit, three trim modes/audio, subtitle/rotation/VFR and source AV1AN CPU gates using native Windows tools.
