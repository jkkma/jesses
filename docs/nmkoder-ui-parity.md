# Exact Nmkoder main UI contract

Source is local fork `a7e9731`. This replaces prior Jesses-only default/UI substitutions at the user's explicit instruction. This inventory describes controls and behavior, not an implementation-complete claim. Auxiliary dialogs are specified separately in [Nmkoder dialog inventory](nmkoder-dialog-inventory.md).

The lists below inventory the fork itself. Under the later CPU-only scope, its hardware video encoder choices and hardware-specific argument rows are excluded from Jesses; Vulkan/libplacebo and GPU processing are retained. See [CPU-only policy](cpu-only-encoding.md) and [catalog dispositions](encoder-catalog-parity.md).

## Main navigation and defaults

Exactly six top tabs, in order: **File List, Track List, AV1AN, Quick Convert, Utilities, Settings** (`Views/MainWindow.axaml:38,138,199,511,803,929`). AV1AN subtabs: **Video, Audio & Tracks, Av1an Options, Advanced**. Quick Convert subtabs: **Video, Audio, Subtitles, Metadata, Advanced**. Global log panel and footer remain visible across tabs.

Quick Convert offers, in order: Copy Video Without Re-Encoding; Disable (Strip Video); H.264 / AVC (x264); H.265 / HEVC (x265); H.264 / AVC (NVIDIA NVENC); H.265 / HEVC (NVIDIA NVENC); VP9 (VPX); AV1 (SVT-AV1); AV1 (AOM); GIF [Animated GIF]; PNG [Image Sequence]; JPEG [Image Sequence]. These five software encoders are the standalone Direct* implementations, not FFmpeg wrapper choices (`UI/Tasks/QuickConvertUi.cs:802`; `Data/CodecUtils.cs:35`). Library encoders remain the ladder's implementations.

## Run, file mode and shared track authority

`SelectedTask` is Convert on Quick Convert, Av1an on AV1AN, the selected card on Utilities, and **None on File List/Track List/Settings**. Run is disabled for None. The remembered `LastTaskTab` is for batch-name preview only; it does not make Run dispatch an old task (`MainWindow.axaml.cs:282–300,527–543`). Utilities starts with no selected card (`MainWindow.Utils.cs:17`). Button text is Run: <task> or Run Batch: <task>.

File List mode is global: **Muxing Mode - Merge all loaded files into one output** or **Batch Processing Mode - Run the task on each file separately**. Mux is the fresh zero-index/default mode; its explicit Load Tracks and double-click actions determine which loaded files contribute tracks. The batch naming field is visible only in Batch. Track selection/order and default-track selectors are shared source-scoped state, not unrelated copies per tab. Checkboxes change inclusion; clicking track text only selects the details. Ordering is the Track List order. Default Audio/Default Subtitles selectors are rebuilt from checked tracks (`MainWindow.StreamList.cs:74+`). Track up/down appears for one selected row; Extract appears only for an attachment. Batch does not allow manual track selection.

Batch runs eligible task against files sequentially. It does **not** offer batch for Concatenate, Get Metrics, Show Bitrate Chart, or Sample Encodes (`Main/RunTask.cs:411–424`). This means Jesses' Run utility for all files option on a ladder would be an extra, not source parity. A running batch owns busy state across row boundaries; it blocks the track panel and disables default-track changes/reorder actions. While running, Run is hidden, Stop and Pause appear where cancellation is allowed. Pause toggles to Resume; completion/failure/cancel clears suspension. Changing the viewed tab during a run does not change its immutable task (`MainWindow.axaml.cs:338–388`).

The global footer has Current Action, progress/indeterminate bar, **Shutdown when done**, Pause/Resume, Stop, Run. Shutdown is session-only, off initially, with a 60-second cancelable countdown. The global log offers Copy, Save…, Log Folder, Clear; it is resizable and stops auto-follow when scrolled up. Per-file queue status appears on File List rows during a batch, rather than a separate queue settings dashboard.

## Conditional screens and persistence

Copy/Strip video disables quality mode/quality/preset/color format/frame rate/crop/resize/borders; fixed GIF/PNG/JPEG hides Container and disables rate-control selection. Encoder changes refill quality/preset/color values from the chosen encoder. Quick audio Copy/Strip disables bitrate/channels/loudness. Per-track audio mode shows Configure and disables common bitrate/channels (`QuickConvertUi.cs:506–542,612–643`).

Deinterlace rows appear only when source fields warrant them. Quick offers BWDIF and QTGMC controls, with one-frame-per-field checked by default; AV1AN deliberately does **not** offer QTGMC (source tooltip at MainWindow.axaml:367). Tone Mapping appears only for applicable HDR/Dolby Vision sources and is disabled for copy/strip. Grain synthesis is enabled only for the two AV1 families, and selected mode alone exposes its numeric/table/preset/denoise panels (`GrainSynthUi.cs:164–220`). Full lists and dialog settings are in the auxiliary inventory.

Quick Convert restores/saves **none** of its job settings between launches (`MainWindow.QuickConvert.cs:160–186`). AV1AN Video also restores/saves none; its Audio & Tracks and custom filter rows do persist (`MainWindow.Av1an.cs:353–392`). General settings, main tab/window/log layout, file-list mode, recent/picker folders and utility configuration persist. Do not preserve a previous encoder/CRF/crop/resize as an accidental extra default.

## Jesses controls requiring removal or source mapping

- No separate backend chooser: AV1AN and Quick Convert are distinct task tabs.
- No separate manual HDR metadata panel: source manual metadata and import fields are corresponding Advanced catalog rows (see 375-row source extract); typed backend validation remains internal.
- No primary ConstantQP or Lossless mode toggle: source Quick quality modes are the three listed above. NVENC rc remains its Advanced grid setting; backend ConstantQP support needs a source-row mapping.
- No exposed 5fish/HDR fork chooser or research preset/quarter-CRF controls: source offers one SVT-AV1 identity and whole quality ranges.
- No separate qualification, tool-status, recovery dashboard, codec-range matrix, analysis export/options screens, generic filter schema/plan IDs or backend execution state controls. Expose only the source's Resume… / Clear Temp… under AV1AN Output Path, normal Run/Pause/Stop, source Advanced filter grid, dialog/context actions and log.
- No arbitrary per-track media processing cards outside source Audio configuration/Track List/Metadata screens.
- Existing complete backend features are retained internally; hiding Jesses-only controls does not authorize deleting the feature implementation or source integrity safeguards.

## Global context-menu and mode-transfer details

- File Sort has exactly Name (A-Z), Name (Z-A), Size (Largest First), Size (Smallest First), Most Recent First, Oldest First. Name compares SourcePath, size compares source Size, date compares FileInfo.LastWriteTime; a directory/image sequence has DirectoryInfo and no FileInfo, so date is unknown rather than an invented import date (`MainWindow.FileList.cs:320–338`; `Data/MediaFile.cs:48–68`).
- Track Select menu: Check All, Check None, Invert Selection, All Video Tracks, All Audio Tracks, All Subtitle Tracks, First Track Of Each Type, First Track Of Each Language Per Type. Track Sort: Language/Title/Codec, each A-Z and Z-A (`MainWindow.StreamList.cs:143–188`).
- Default Audio selects the first checked audio if no checked track is already marked default; subtitles include None before the checked subtitle choices. Selection is built from checked rows and source-scoped track identities, never only a global numeric stream index (`MainWindow.StreamList.cs:74–140`).
- Switching Mux→Batch clears the currently assembled Track List when one exists. Switching Batch→Mux auto-loads the one file only when exactly one file exists and the Track List is empty. Switching modes updates the title [Mux]/[Batch] and the batch naming panel (`MainWindow.FileList.cs:85–111`).
- AV1AN option defaults are code-derived: split Scene Change Detection, chunk-method index1; concat index0; chunk order index0. Scene slices=half cores clamped1..8. Worker baseline=ceil(cores×0.4) clamped2..32; total thread budget=max(2,round(cores×0.8)); threads/worker=ceil(budget/workers) clamped2..16. SVT subtracts2 workers from the baseline with a floor of1, retaining the baseline for other encoders (`Av1an.cs:1483–1526`; `Av1anUi.cs:154–216`; `Config.cs:352–369`). Markup4 workers/2 threads are not the actual machine-derived opening defaults.
- Source container choices are MP4, MKV, WEBM, MOV, M4A, OGG in enum order; Quick opens MKV. AV1AN offers only MKV, WEBM, MP4 in that order (`Data/Containers.cs:10`; `Av1anUi.cs:85`).
- Loudness choices: No normalization; -14 LUFS (YouTube, Spotify); -16 LUFS (podcast, mobile); -23 LUFS (EBU R128 broadcast) (`Data/LoudnessConfig.cs:74–81`).
- Quick deinterlace choices in order: Automatic, Disabled, QTGMC, BWDIF, YADIF; QTGMC is the first-use choice. AV1AN removes QTGMC and opens Automatic (`DeinterlaceUi.cs:58–108`). Rows still depend on the source field verdict and manual edits are protected from late analysis.

## Backend compatibility actions exposed by exact source settings

- Source CRF0, whole quality ranges and visible preset limits must be accepted or clearly mapped; the old Jesses minimum SVT CRF1 and research/quarter-step UI are not the source contract.
- Source Spline/Area resamplers need corresponding typed/runtime values; first-use source resampler is Bicubic. Preserve old saved omitted-filter meaning internally while sending an explicit source default for new UI jobs.
- Source most-recent/oldest sort requires actual optional file modification metadata, not list insertion time; sequence folders have no FileInfo date.
- Source Settings must persist and actually consume console policy, auto-crop samples, keyframe interval, stream-number display convention, MP4 faststart, AV1AN console policy and reset categories. A cosmetic checkbox without its consumer is not parity.
- No backend deletion is authorized by this UI inventory. Existing image export, typed HDR, safe process/job control and other adapters can support the corresponding source control while remaining internal.

The user subsequently requested a paper-and-ink theme. Source parity applies to controls, settings, defaults and behavior; it does not require the fork colors or fonts.
