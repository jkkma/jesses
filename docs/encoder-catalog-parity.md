# Fork encoder catalog parity

The pinned extract `tests/fixtures/nmkoder-encoder-catalog.json` preserves all six
original fields in all **12 catalogs / 375 rows** from fork commit `a7e9731`.
The current dispositions are **297 CPU scalar rows**, **11 typed grain/HDR
resource rows**, and **67 hardware rows excluded by the later CPU-only user
request**. Vulkan/libplacebo Spline processing and GPU metrics remain supported.
This is inventory coverage, not375 independently qualified tool executions.

`jobs/parameters/source_specs.rs` is generated by `scripts/generate-encoder-source-specs.py`; original help text is retained. Existing native x264/SVT/AOM/VPX/x265 routes retain their command builders, while CRF ladder wrappers share the complete source scalar specifications. The FFmpeg x265 and VP9 CPU routes use those same wrapper specifications. Hardware catalogs are excluded by the latest user scope. User strings never become option names.

Values are bounded and typed, including signed whole numbers, colon-separated pairs, choices, and distinct choice lists. The native x264 Boolean controls emit `--flag` / `--no-flag`; x265's nested pairs become comma pairs so they cannot split the colon-delimited dictionary. Whole negative sentinels remain explicit. Decimal controls are nonnegative, at most three fractional places; x265 qcomp has minimum 0.5 and I/P and P/B ratios exceed 1. Installed help filters options and enumerated FFmpeg/AOM/VPX choices. Nested libx265 receives a bounded real initialization probe before work, and ladder wrapper values receive independent plus combined real probes; unsupported preset rows are reported, while unsupported manual values reject the request.

Controls that would change frame-count verification (nonzero `drop-threshold`), primary lossless/bit-depth mode, or the CRF ladder's rate control require the typed job setting. These are explicit consistency constraints, not tuning flags silently omitted. Source AOM corpus complexity requires single-pass target-bitrate mode. Hardware video encoding is removed by explicit user request; historical enum/quantizer records remain readable and active requests are rejected. Vulkan/libplacebo Spline processing and GPU metrics remain supported. The exact SVT 4.2 high-bit-depth mode-decision plus overlays pair is preserved with parallelism level 1 after native and wrapper crash reproductions at higher levels. Explicit 8-bit output rejects that high-bit-depth control before queueing; 8-bit ladders report its omission.

Validation: `cargo test -p media-runtime --lib jobs::parameters::tests --locked` passes9 tests (one installed-tool test separately ignored). The full-row disposition test asserts exactly375=297+11+67 and checks typed examples. `cargo test -p media-runtime --test parameter_jobs --locked -- --ignored --nocapture` passed 2/2 with real FFmpeg9.0.1, x264, libx265, libvpx-VP9, SVT4.2.0, 5fish and HDR executables. The expanded job covers all six new x264 toggles/scenecut, signed/pair values, nested x265 controls and VP9 controls, verifies decoded frames/B-frames and preserves source hashes. This is representative execution of new semantics, not an exhaustive encode of every possible value.
