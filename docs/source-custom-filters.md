# Source custom FFmpeg filters

The source grid is a list of arbitrary FFmpeg filter strings. The source adapter preserves every editable row, including blanks, paths, backslashes and more than sixteen rows. Request construction removes only rows whose .NET-trimmed UTF-16 length is at most two; surviving strings retain their exact bytes and order. This is separate from the historical explicit API's narrower filter grammar.

Source authority: `Nmkoder/UI/Tasks/QuickConvertUi.cs:2067–2069` and `Av1anUi.cs:772–774` omit whitespace-only rows without modifying surviving strings. Their final chain construction (`QuickConvertUi.cs:1897`, `Av1anUi.cs:652`) removes trimmed strings of length at most two. .NET whitespace includes NEL U+0085 but excludes BOM U+FEFF; .NET string length counts UTF-16 units. Quick custom rows occur after picture/grain processing and before GIF's forced palette graph.

The source request uses the internal `sourceFilters:true` discriminator with `av1anFilters` for CPU/AV1AN and `processing.filters` for selected-video image export. It adds no control. Empty/short rows produce no discriminator or filter array. The implicit fixed-image route with no checked video continues to omit picture processing. Batch and held requests freeze the strings before asynchronous destination/tool preparation.

AV1AN source preference storage has a source-aware parser. It preserves raw editable rows and removes the historical sixteen-row, path and per-row-size restrictions only for this source surface. NUL remains invalid. Other preference fields retain their typed validation. Saved rows are restored before automatic saving starts. Storage quota/security failures are reported in the activity log while the current draft remains usable; a failed write preserves the existing stored value.

## Native execution and recovery

The source mode keeps the frozen rate-control calculation and command precedence. SVT/AOM/VPX timed streams obtain their nominal rate from the actual Y4M producer. Source x264/x265 Annex-B output is wrapped at the source/UI rate; an arbitrary raw `fps` row does not silently change that wrapper rate. A frozen pre-filter `--sar` no longer overrides the actual Y4M SAR for source x264/x265. The legacy explicit API retains its prior arguments.

Private producer statistics use separate identity-guarded files per process/output stream. Records are read with bounded memory and cancellation after process exit; malformed, truncated, skipped, mixed-stream and altered-clock records fail. The user graph is not replayed to obtain reference statistics. Geometry/SAR and complete decoded coded-output clocks establish the actual output contract. That contract changes only encoded-video expectations; copied-track clocks, metadata, source guards and no-clobber publication remain enforced.

Selected-video source images use a single actual graph into an owned encoded spool. GIF appends the fork's split/palettegen/paletteuse graph after custom rows in that same invocation. PNG/JPEG/GIF are completely decoded and validated as their selected image family; sequence expansion stream-copies packets with hash equality and atomic publication. Normal and unchanged-confirmed source paths execute native argv. Only explicitly edited held programs use the shell broker. Source mode does not run separate custom-filter reference/palette passes. It incurs the same encoded-spool temporary disk use as the already-qualified edited-image route.

QTGMC script preparation is allowed before review; custom filtering follows confirmation. The fork writes its script before command construction (`QuickConvert.cs:931`), builds the FFmpeg arguments at373–393, reviews them at402–414, and starts the VSPipe prefix through `AvProcess.FfmpegSettings.PipeFrom` at432. Native held standalone source-filter programs now include their owned QTGMC preparation stage and defer execution until confirmation. Only the source-filter intermediate's frozen `-r` override is removed, so raw FPS rows reach the downstream encoder/image muxer. Private producer counts and full cached-output decoding validate the result.

Standalone source-filter QTGMC recovery has explicit Deferred/Rendered internal states. Original source/tool/settings/raw-argument authority is frozen before review. After unchanged confirmation, the actual cache receives both its file SHA-256/identity/length and complete decoded-frame fingerprint; it is verified before use and before sealing the encoded checkpoint. The temporary cache is not adopted as a durable recovery input. A verified unchanged encoded checkpoint resumes without rendering/filtering again. Legacy QTGMC decoded fingerprints remain strict.

AV1AN invokes raw rows within each actual queued chunk, including QTGMC input. The QTGMC cache retains typed reconstruction while raw rows stay in the engine's `--ffmpeg`/recovery receipt. Its existing trusted queue/done/completed-chunk receipts and real FRAME MISMATCH gate retain frame-count authority. Unknown/foreign files and altered/missing queue or sealed chunk bytes reject recovery. Mutable done.json is rebuilt exclusively from sealed manifest receipts, so forged completion entries are discarded. Source target probes remain intentionally unfiltered under the previously qualified source-probe flag; legacy explicit transformed-probe behavior is separate.

## Remaining scope

The finite source-filter matrix above is closed. It does not claim every arbitrary FFmpeg graph succeeds: the selected encoder/muxer and the fork's actual per-chunk count rules still govern operational validity. Midstream geometry/depth changes that the selected codec cannot represent fail actual encoding/strict decoding. There is no added filter whitelist or visible control.

The source's anamorphic-only final `-aspect` calculation predates arbitrary rows (`GetMuxAspectArgs`, QuickConvertUi.cs:1520). The source-filter consumer intentionally preserves the observed filtered SAR instead of forcing a stale pre-filter planner aspect. The actual anamorphic fixture above proves corrected DAR8:3, the fork-style stale DAR4:3, and legacy isolation. This is a source-bug correction rather than packet/metadata-identical parity.

AV1AN None-split/max-chunk and source-profile New Settings have their own implementation/evidence owner. The raw-filter legacy explicit New proof above rebuilds chunks; the fork's source New profile can retain old scenes/queue/completed chunks while new global raw rows affect remaining chunks, including a mixed-resolution result. That source-profile consumer/recovery qualification is not established by the legacy fixture. The completed combined single-layer DV tone-map trim/burn/rotation/VFR and compatible AV1AN CPU gates are in [source-dolby-combinations.md](source-dolby-combinations.md). Dual-layer/FEL reconstruction is not claimed.

The final source trim follow-up preserves arbitrary-filter state: source Quick uses output-side Exact/Frame seek after the complete graph, while InputSeek precedes the original decoder. Standalone `sourceTrim + sourceFilters` and the corresponding source fixed-image route now keep that placement, including original subtitle clocks. The historical explicit raw API retains its former filter-local trim behavior. `source_filter_trim_jobs.rs` proves three CPU trim modes, an exact 30-frame PNG sequence, one side-effect graph execution per operation and legacy state isolation against independent literal FFmpeg references.
