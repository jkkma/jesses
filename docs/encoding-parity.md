# Encoding workflows migrated from Nmkoder

The immutable encode request now selects `videoMode`: `encode` (the historical default), `copy`, or `drop`. Copy preserves the selected video packets while applying the ordinary selected-track audio conversion settings. Drop accepts audio-only sources and audio selected from a video source. Neither path discovers or requires a video encoder. Saved requests without the new field retain their historical behavior and serialized identity.

## Framing

`VideoFraming.resize` holds the resize intent until a source is inspected. Its modes are Fit box, Width, Height, Percentage, and Exact size. Exact size can pad, crop, or stretch. The legacy `resizeWidth` field remains readable; a present resize object takes precedence.

Fit boxes follow portrait orientation. Width, height and fit targets obey the upscale switch; a percentage above 100 explicitly requests an upscale. Dimensions round to the configured even alignment. A fit cannot grow past its box; crop-to-fill rounds outward before an even-centered crop. Optional anamorphic correction measures the cropped source display ratio before rounding.

Ratio borders add black bars without scaling to 16:9, 4:3, 1:1, 9:16, 64:27, or a custom ratio. They follow crop and resize. Explicit pixel borders run last. The frame size and the bar offset round separately, so an otherwise odd offset is moved to an even chroma coordinate and the remaining pixels go to the opposite bar. Black levels remain explicit at the output range and depth.

The checked geometry range is even dimensions from 2 through 16384, below FFmpeg's safe 260-megapixel frame bound. Each selected encoder can impose a smaller size limit. Ordinary encoding preserves source SAR when no resize or explicit aspect transform is requested.

## Audio-only and copy-video conversion

The conversion pipeline uses the same immutable job queue, selected-track ordering, source identity guards, cancellation, history, packet verification, decoded audio timeline checks, and no-clobber publication as video encoding. Audio encoders include AAC, Opus, FLAC, MP3, Vorbis and E-AC-3. Settings are validated against the selected stream's sample rate and layout before processing.

M4A accepts AAC or ALAC audio. Ogg accepts Opus, Vorbis or FLAC audio. Existing MKV, MP4, MOV and WebM compatibility checks still apply. Ogg has per-stream comments rather than global container tags; the writer preserves global tags as `JESSES_CONTAINER_*` comments on each audio stream and verifies their values. A sole Ogg audio stream is implicitly the playback default. Authored multi-track dispositions and chapters require another container; incompatible requests fail before encoding.

Audio-only time trimming picks decoded samples in the requested half-open interval, rebases their timestamps, clips readable subtitle cues and chapters, and verifies the resulting audio sample clock. Selected audio must be converted to guarantee sample boundaries. Video-copy trimming first makes and verifies a lossless keyframe cut, then converts the selected audio. It logs the actual preceding keyframe and pre-roll. This fork-equivalent copy-cut route uses the first video of one source; mixed-source trim remains available through video encoding.

## Source analysis

`detect_fields` uses declared field order when available. Otherwise it samples three stretches with `idet`, checks consistent field order, and measures alternating separated-field motion to reject progressive vertical-pan false positives. Repeated-field evidence flags possible telecine. Cancellation, bounded tool output/time, and source fingerprints apply throughout.

`snap_keyframe` finds the last keyframe at or before a source position. It queries a 20-second window, then 120 seconds, and only then the whole preceding interval if needed. An exact keyframe boundary is retained. This is a read-only proposal; it does not change an immutable queued request.

## Unspecified SDR metadata

Explicit color metadata remains authoritative. Unspecified SDR fields use a conventional interpretation: a known compatible SDR tag supplies omitted peers; otherwise HD/RGB uses BT.709, PAL-height SD uses BT.470BG, and other SD uses SMPTE 170M. Untagged YUV defaults to limited range and RGB/JPEG pixel families to full range. Missing subsampled chroma placement uses the encoder-compatible conventional interpretation. The job log states inferred fields. Every raw decoded frame is still compared against the original stream metadata; output metadata must match the interpreted output contract.

SVT's limited-range requirement is met by explicit full-to-limited sample conversion rather than rejecting full-range SDR YUV. Positive constant source and requested output rates from 0.001 through 1000 fps are representable, subject to encoder limits and the existing bounded rational terms. Explicit BT.2020/PQ 10-bit YUV with unspecified range uses the same limited-range interpretation; metadata cannot turn SDR pixels into HDR.

## Canonical source clock and orientation

Nonzero video origins, authored display rotation and variable timestamps use an explicit lossless FFV1 source only when required. The selected video origin becomes zero; copied tracks keep their original relative timing, including an audio lead before zero. The original request remains authoritative. VFR becomes an explicit CFR clock with frame duplication/drop; this is not VFR passthrough. Coded-grid crop edges rotate with the image, SAR inverts for quarter turns, and resize/borders operate on the resulting geometry. Batch preview predicts that same geometry without writing a derivative.

The normalizer independently compares complete decoded pixel hashes, original/derived static HDR metadata, copied packet contents and shifted timestamps. PQ static HDR stays HDR; HLG enters its explicit tone-map workflow after lossless preparation. Metadata checks scan every original frame, including when HDR rendering data is absent from headers. Dynamic HDR cannot be silently duplicated, dropped or discarded. Arbitrary projective display transforms and interlace/telecine reconstruction combined with canonicalization require an explicit rendered-source workflow; right-angle progressive transforms are qualified.

Disk preflight conservatively budgets raw high-depth frames, copied streams and mux overhead. Stream duration is interpreted as a span while Matroska DURATION tags represent track ends; a shifted origin never subtracts from a TS duration span. Original and derived complete file hashes and filesystem identities bind durable recovery receipts. Cancellation removes only receipt-proven artifacts; stop/restart/resume reuses a verified canonical source. Success and explicit recovery discard remove the owned derivative. Symlinks, foreign entries, changed inputs and modified derivatives reject reuse/cleanup rather than authorizing unrelated deletion.

## Authored HDR metadata and imports

`hdrMetadata` optionally overrides mastering-display coordinates in 1/50000 units, luminance in 1/10000 nit units, and MaxCLL/MaxFALL. Coordinates, a nondegenerate primary triangle, luminance order/range and meaningful MaxFALL/MaxCLL ordering are validated; zero unknown content-light values remain valid. Standalone SVT, AOM, x265, FFmpeg x265 and AV1AN x265/SVT consume the same typed values. Source validation retains the original metadata contract; output validation checks the authored values.

External resources accept complete HDR10-compatible profile 8.1 RPU records without reshaping, or HDR10+ SceneInfo JSON with consecutive SequenceFrameIndex values. Each resource must contain exactly one record per unchanged source frame and be at most 256 MiB. Import requires a metadata-linked SVT5fish/SVT-HDR build, a complete untransformed source and standalone encoding or one AV1AN chunk. Trim, resize, crop, frame-rate/deinterlace filters and parallel metadata imports reject before encoding: the fork's raw resource flags do not slice metadata for chunk-relative frame numbers, so accepting those combinations would silently attach records to wrong frames. Static metadata works with ordinary multi-chunk AV1AN encoding.

Resources are identity-guarded, staged through native argv-safe paths and included in recovery fingerprints. Metadata-loading diagnostics from fork binaries go to logs while a guarded native path receives IVF. Before publication, a bounded streaming verifier reads the final container's AV1 metadata at presentation timestamps: HDR10+ T.35 payloads must be byte exact; every parsed RPU field must match after normalizing only extension-block ordering and its derived CRC. Native parsing validates the original CRC. Omitted, duplicate, reordered-to-wrong-frame or changed metadata fails the job. Dolby Vision outputs also require a profile 10, HDR10-compatible, uncompressed RPU/base-layer configuration without an enhancement layer. MP4 explicitly preserves its dvvC signaling. These checks establish metadata/configuration integrity; they do not claim playback certification.

The native parsers are pinned to [dolby_vision 3.4.0](https://docs.rs/dolby_vision/3.4.0/dolby_vision/) and [hdr10plus 2.1.5](https://docs.rs/hdr10plus/2.1.5/hdr10plus/), both MIT-licensed and recorded in Cargo.lock. No metadata CLI is required at runtime.

## Validation

`crates/media-runtime/tests/migration_encode.rs` synthesizes all sources locally. Its opt-in real-tool checks cover true audio-only input, M4A/Ogg conversion, copied-video conversion, sample and keyframe trims, chapter/metadata/track-order preservation, exact keyframe snapping, field detection, and all seven resize/fill variants through lossless x264. The framing unit matrix separately checks portrait fit, anamorphic rounding, alignment, exact fills, border ratios, and pixel-range black values.

`migration_recovery.rs` covers normalized standalone two-pass and partial AV1AN stop/restart/resume, cancellation cleanup, discarded sources, tampering and foreign-file preservation. `migration_hdr.rs` generates its own metadata and verifies authored HDR on decoded output frames, shifted/VFR/rotated PQ and HLG with audio, both linked SVT forks, MKV/MP4 signaling and single-chunk AV1AN imports. Parser/recovery units cover malformed resources, frame count/index mismatches, semantic changes and changed external resource files.

## Whole-source picture export and quality comparison

`ImageRequest::Export` accepts `fullSource:true` and shares Quick Convert trim, framing, temporal processing, tone mapping and validated custom filter rows through `processing`. The runtime scans the processed source to establish the actual output count. It streams frame hashes and frame metadata, rather than deriving the count from duration or retaining every record in memory. Whole-source export has no 10,000-frame ceiling; disk and descriptor preflight protect the selected output directory. GIF uses the source palette range 3–256 (default128), two-pass palette generation/use and Floyd–Steinberg dithering. JPEG uses quality1–31 (default3) and 420/422/444 YUV; PNG keeps RGB/alpha 8/16-bit choices and compression3. Existing explicit partial exports remain compatible.

`DeinterlaceSettings.engine` selects BWDIF or YADIF. Omission preserves the old BWDIF wire representation. Both engines retain the same checked parity, frame/bob cadence, geometry and output progressive constraints. Explicit operation accepts declared progressive input as the source UI does; automatic selection still uses the shared source resolver and skips progressive/unknown sources.

Quality comparison accepts `fullSource:true` without a frame count. Both sources are decoded and checked in parallel with a bounded timestamp channel: actual counts, relative clocks and dimensions must match. Complete PSNR/SSIM/VMAF report records contribute to the score while chart samples remain bounded. Existing explicit partial comparisons retain their original limits and behavior. The real quality regression compares 60,001 paired frames, then rejects a shorter candidate.

The image regressions export and verify 10,001 frames, test no-clobber and active cancellation, check palette size/JPEG quality and all YUV layouts, and exercise shared time trim, crop/resize/borders, FPS, PQ tone mapping and a custom filter. Both image and video tests exercise BWDIF and YADIF; video tests check retained source field rows for top/bottom-first and frame/bob modes.

## ColorData declaration editing

The source dialog's independent color-space and HDR checkboxes map to `copyColor` and `copyHdr` (both defaulttrue for old requests). `inPlace:true` rewrites only the explicitly selected target. Omission retains the old `.mkv` copy-to-new operation and its no-clobber rule. Selecting neither category, selecting the same file as donor and target, or selecting HDR from a donor without HDR is a no-op. The read-only `read_color_metadata` analysis query returns all four tags, mastering coordinates/luminance, content-light values and available Dolby Vision profile/compatibility without changing either file.

Editing first writes an owned stage, verifies every selected/effective metadata property, restores the target container family, then verifies stable stream/container metadata, chapters and complete packet bytes/timing. ColorData edits declarations, not pixels or dynamic HDR payloads. MKV, MP4, MOV and WebM color edits, plus MKV/WebM static-HDR edits, have real positive proofs; the format signatures are checked. A target format/codec combination that cannot retain the requested declaration fails before replacement. In particular, the tested H264 MP4/MOV cannot replace static HDR content-light values while retaining its original SEI packets: the operation rejects and its bytes remain unchanged. Jesses preserves actual container format instead of reproducing the fork's Matroska-under-an-ISO-suffix overwrite bug.

A verified sibling replaces the selected target atomically: Linux/macOS exchange identities and validate the displaced original before deletion; Windows uses `ReplaceFileW` with a private backup and identity checks. A changed target triggers guarded rollback, and uncertain data is retained. Cancellation is honored until the synchronous commit boundary. Symlink targets are rejected. Linux unit tests cover success, cancellation at that boundary, concurrent replacement and preservation of foreign data; host-specific Windows/macOS replacement execution remains the corresponding platform CI responsibility. Integration tests cover all four checkbox combinations, unchanged donor bytes and decoded pixels, legacy copy-to-new no-clobber, preserved flat metadata/language, common container signatures and rejected-operation preservation.

## Folder image-sequence sources

`import_image_sequence` is a cancellable analysis action, not a user-facing video export. It takes `ImageSequenceImportRequest {directoryPath,frameRate:{numerator,denominator}}` and returns an ordinary `MediaFile` with optional `source:{kind:'imageSequence',directoryPath,frameRate,extension,frameCount,sequenceFingerprint}`. The source FPS dialog defaults to 30; native admission accepts reduced positive rational rates 0.001–1000 within FFmpeg's signed integer time base. `MediaFile.path` is the guarded processing source, while its name, original image codec/profile/pixel metadata, chosen FPS, size and source descriptor describe the original folder. File List/recent entries/default output paths must use the original directory; native batch `{name}` retains the complete dotted folder basename and `{ext}` is empty. Unknown source bitrate stays unknown.

The fork's `MediaFile.InitializeSequence` and `IoUtils.GetFilesSorted` select one extension in stable filename order, not natural numeric order. Supported top-level image extensions are PNG, JPG, JPEG, BMP and WebP, matched without case. Jesses selects the first supported image extension after culture ordering; nested folders and unrelated files are not frames. This avoids the fork's failure when an alphabetically earlier non-image extension becomes its concat input. Each selected entry must be one still with matching geometry, bit depth and pixel layout; unsupported layouts reject explicitly. Numeric patterns are unnecessary. PNG with 16-bit alpha and JPEG have positive, complete ordered decoded-pixel proofs; temporary storage preserves RGB/alpha samples instead of flattening transparency.

Ordering uses the effective OS/.NET-style culture and stable, nonnumeric ICU collation. Windows queries the user default locale; Unix follows ICU's LC_ALL/LC_MESSAGES/LANG precedence and maps C/POSIX to invariant collation; macOS uses the current native locale when environment culture is invariant. The receipt pins the locale, ICU engine version and exact ordered list. Existing sources verify membership and file identities without reordering after a locale change. The runnable `.NET 10` fixture in `tests/fixtures/sequence-sort` matches actual source `OrderBy` against ICU 2.3 on 52 mixed case/accent/punctuation names: local invariant/current, en-US, es-PY, sv-SE, tr-TR, de-DE, the legacy German sort-name case, and Swedish/Turkish environment selection. Local execution is Linux; Windows/macOS locale acquisition remains native CI qualification. A POSIX `@collation=phonebook` experiment aborts the installed .NET host before the fixture can run, so that environment is not claimed equivalent. See [ICU collation](https://docs.rs/icu_collator/2.3.0/icu_collator/) and the [.NET locale implementation](https://github.com/dotnet/runtime/blob/main/src/native/libs/System.Globalization.Native/pal_locale.c).

A private, owned materialization verifies every decoded frame's count/order/geometry/pixel hash and chosen clock before publication. Its content-addressed receipt binds original directory/file identities, complete hashes, order/FPS, original stream metadata and the derived file identity/hash. Every ordinary source open/recheck therefore protects queued requests, preview, trim, encoding and restart/resume. Sources are never rewritten. Disk/descriptor/receipt budgets bound resources without an arbitrary frame-count cap. Cancellation removes only tracked staging entries; no-clobber cache publication and release preserve foreign files. Shared source leases and queue/recovery admission prevent release while a preview, active job or durable recovery uses it. `release_image_sequence {inputPath,sequenceFingerprint}` deletes only verified cache-owned artifacts; closing the app does not release sources needed for restoration.

Actual source restrictions remain explicit: AV1AN, lossless cut, concatenate, grain, CRF ladder, cadence/deinterlace export and in-place container metadata editing require ordinary encoded media. Quick Convert, image exports and read-only source previews retain their normal applicable format checks. Packet-bitrate charts are guarded for folders: reporting FFV1 cache packet sizes would misrepresent the source. A per-still compressed-payload chart adapter is outside this bounded import phase and remains an explicit residual if such folder charts are required.

`image_sequence_source.rs` covers nonsequential PNG16-alpha/JPEG order and FPS, original metadata/bytes, re-probe identity, thumbnail/crop, real lossless 4:4:4 trim encoding, mutated originals, foreign cache/no-clobber, active cancellation cleanup, and native two-pass stop/restart/resume with changed-image rejection and blocked recovery release. Guard units cover active leases, stale-source cleanup, receipt/order/FPS tampering, culture ordering and original dotted names. The real JPEG proof also corrected lossless verification's former 4:2:0-only byte budget; it now validates identical declared planar 4:2:0/4:2:2/4:4:4/depth before exact byte comparison.
